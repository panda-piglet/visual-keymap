## 5. 风险评估

### 尚需优先验证

1. **R-03 不可写目标**：这是剩余的直接文件完整性失败路径。覆盖成功不能证明失败写入安全。
2. **R-12 单个宏编辑隔离**：多个未绑定宏“不丢失”不能证明编辑其中一个时不会写到另一个对象。26.3 隔离测试仍为发布前关键项；26.2 对照可以由维护者明确豁免并披露。
3. **R-11 CommandKeys GUI/触发**：快照排除和未绑定宏保留不覆盖 profile、搜索、组合编辑和实际宏触发。
4. **R-13 明确跨 Provider 联合编辑**：现有冲突反馈未说明 Provider 范围。

### 可作为预发布已知限制

- R-01 的完整语言/Scale 视觉矩阵、R-14 Mod Menu 两种返回链和 R-20 外部 Provider 完整 GUI，可以在预发布首轮继续收集，但必须披露未验证范围。
- F25、M6～M8 和 26.3-only 物理键缺少硬件；编码、往返和不可应用保护已经通过，不等于数据安全失败。
- MaLiLib 单/双键及提前释放是稳定版完整交互证据缺口；四键上限和实际使用已经通过。
- version 1 modifiers、CommandKeys 不导出、重复 ID 人工消歧和未知 version 均为已锁定历史语义，不是本轮缺陷。

## 6. 发布就绪性结论

- **数据完整性现状**：没有发现新的数据损坏、静默丢失或回归；复杂配置多次重启、多个未绑定宏保留和导出覆盖均提供了正面证据。但 R-03 不可写失败路径和 R-12 单对象编辑隔离尚未关闭，因此不能说数据完整性风险已经全部验证完毕。
- **预发布版**：技术基础继续满足 `READY FOR PRE-RELEASE`，但按 Phase 5A 原门槛，当前仍是**有前置条件，尚未批准公开发布**。至少应完成 R-03、R-12，以及 R-11/R-13 的缩减关键步骤；其余未完成项需要逐项披露或明确豁免。
- **稳定版**：`NOT YET READY FOR STABLE`。真实 GUI/触发/Provider 回调和返回链仍有明确缺口。
- **Phase 5C**：尚不建议把 Phase 5C 视为最终发布执行阶段。可以预先讨论版本号、README、许可证和更新日志，但在最小高风险补测完成或维护者书面接受对应风险前，不应创建 tag 或公开预发布。
