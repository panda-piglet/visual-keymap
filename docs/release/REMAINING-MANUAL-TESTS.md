# Visual Keymap 26.3 最小剩余人工测试

## 1. 使用方式

本清单只保留现有证据无法替代的真实 GUI、物理触发与持久化测试。BUG-01 的 M-01～M-10、BUG-02 的 M-01～M-08、39 项 JUnit、P1–P6 启动、127 扩展键编码表和 217 条 MaLiLib 枚举均已有充分证据，不要求重复。

所有测试使用独立 gameDir 和配置副本。宏只发送无害本地文本；不要连接真实服务器。状态使用 PASS / FAIL / BLOCKED。无特殊硬件时，侧键、F25 和 26.3-only 物理触发可标 BLOCKED，不影响已经通过的数据安全结论。

## 2. 会话 A：P1 原生环境

### R-01 原生主屏、导航与代表性布局

- 模组：Visual Keymap + 必要 Fabric 组件。
- 最少步骤：从 Controls 打开；检查初始未绑定列表；点击一个已绑定键、再次取消、换另一个键；按 Esc 返回 Controls；用中英文各打开一次，并在 GUI Scale 2 与 Auto/较大值各看一次关键区域。
- 预期：选择/取消/切换同步；Esc 返回正确父屏；标题、搜索、键盘、列表、底部按钮无遮挡；两种语言无缺键。
- 风险：中。
- 建议证据：四张截图（英/中、两 Scale）和简短结果记录。
- PASS：无错误父屏、空白、关键遮挡或翻译键泄漏。

### R-02 原生搜索、排序、冲突和编辑触发

- 模组：P1；本地测试世界。
- 最少步骤：用多词/大小写搜索一个绑定；依次切换三种排序并开关冲突置顶；制造一个原生冲突；编辑一个无害动作并在世界中触发；编辑时按 Esc 清空；Reset；用 Done 和主屏 Esc 各离开一次并重启。
- 预期：搜索置顶但不隐藏其他项；排序优先级正确；冲突颜色/tooltip 正确；新键实际触发；清空、Reset 和两种离开路径均持久化。
- 风险：高（用户核心操作与持久化）。
- 建议证据：短录屏、`options.txt` 测试副本、重启后的截图。
- PASS：所有操作与显示一致，重启无额外变化。

### R-03 导出覆盖与不可写目标

- 模组：P1。
- 最少步骤：在专用临时目录导出一个快照；再次选择同名文件并处理覆盖；再对一个明确不可写的临时目标尝试导出。不要使用用户真实配置目录。
- 预期：覆盖行为可预测，成功文件仍是有效 version 1；失败不破坏已有文件、不崩溃。
- 风险：高（文件数据完整性）。
- 建议证据：操作前后 SHA-256、文件内容、`latest.log`。
- PASS：已有文件未被截断/损坏，客户端可继续使用。若平台无法构造不可写目标，记录 BLOCKED 并披露。

## 3. 会话 B：P5 全依赖环境

### R-10 MaLiLib GUI、多键状态机与实际触发

- 模组：MaLiLib 0.30.2、Tweakeroo 0.30.1、CommandKeys、Mod Menu、Visual Keymap。
- 最少步骤：抽查两个 MaLiLib 条目的 category、名称、comment tooltip；用内部 hotkey 名搜索；分别录入单键、按住输入 2～4 键、首键提前释放；Reset；保存、重启；在本地世界触发一个无害热键。
- 预期：显示/搜索正确；最多四键、顺序与释放时机符合基线；Reset 恢复默认；重启保持；实际触发成功。
- 风险：高。
- 建议证据：录屏、代表性 `tweakeroo.json` 副本和重启记录。
- PASS：GUI 状态机、持久化和真实触发三条链均通过。

### R-11 CommandKeys profile、显示、搜索、编辑与触发

- 模组：同 P5；至少两个 profile；准备空/非空名称、首消息空、多消息、单键和组合宏。
- 最少步骤：切换两个活动 profile 并重新打开 Visual Keymap；检查名称和 tooltip；用第二条消息搜索；编辑单键与 limit+主键；清空/Reset；保存、重启；在本地世界触发无害宏。
- 预期：只显示当前 profile；摘要和 `[+N]` 正确；任意消息可搜索；limit 在主键前；配置与触发在重启后保持。
- 风险：高。
- 建议证据：两个 profile 截图、短录屏、测试配置副本。
- PASS：可见行为、写入顺序、实际触发和持久化全部正确。

### R-12 多个未绑定 CommandKeys 宏隔离

- 模组：26.2 与 26.3 各一份隔离 CommandKeys 测试实例。
- 最少步骤：每版建立至少两个完全未绑定宏；记录 Visual Keymap 枚举数量；只编辑其中一个；确认另一个未改变；保存重启。
- 预期：26.3 不会把一个宏的编辑写到另一个宏；与 26.2 的可观察行为一致。
- 风险：高（潜在错误对象写入/数据完整性）。
- 建议证据：两版配置前后副本和条目数量。
- PASS：目标宏唯一变化；若 26.2 本身有相同行为，记录历史限制并停止扩大修复。

### R-13 跨 Provider 冲突、排序和联合保存

- 模组：P5。
- 最少步骤：让 Minecraft、MaLiLib、CommandKeys 各有一个代表绑定，其中两项形成跨 Provider 冲突；检查默认顺序和冲突置顶；分别编辑三项；退出并重启；导出快照。
- 预期：顺序为 Minecraft→MaLiLib→CommandKeys；冲突/排序正确；三类配置各自持久化；CommandKeys 仍不进入 version 1 快照。
- 风险：高。
- 建议证据：冲突截图、三类配置副本、导出 JSON。
- PASS：联合保存无互相覆盖，快照 provider 语义保持。

### R-14 Mod Menu 返回链

- 模组：P5。
- 最少步骤：从 Mod Menu 打开 Visual Keymap；用 Done 返回；再次打开按 Esc；连续打开关闭一次。
- 预期：始终回到传入的 Mod Menu 父屏，无空白、错误引用或焦点异常。
- 风险：中。
- 建议证据：简短录屏。
- PASS：三条返回路径均正确。配置按钮“能够打开”已通过，不需重新证明入口存在。

## 4. 会话 C：P6 外部 Provider

### R-20 外部 Provider 完整 GUI 契约

- 模组：production-smoke 的 P6 外部 Provider。
- 最少步骤：检查名称、comment tooltip、modifier 和 order；搜索并制造冲突；编辑、Reset、离开触发 save；导出并导入该 provider 的 version 1 记录，确认并重启。
- 预期：有效 provider 始终工作，失败 entrypoint 不影响它；回调次数和快照 provider/ID/keys/modifiers 符合既有契约。
- 风险：中高（公开 API 承诺）。
- 建议证据：GUI 截图、导出 JSON、probe 结果文件和重启记录。
- PASS：GUI、回调、保存和快照闭环均通过。

## 5. 可接受的已知限制

- 无 F25、M6～M8 或 26.3-only 物理键：标记 BLOCKED；不重开已通过的编码、碰撞、不可应用与数据保留结论。
- version 1 不应用 modifiers、CommandKeys 不参与快照、未知 version 保持历史接受行为：属于已锁定兼容语义，发布说明中披露，不作为本轮失败。
- 配置文件无效 JSON/只读目录的精确 26.2 对照：若不补测，应列为历史错误处理限制；不得用真实用户配置试验。
- 键帽 6+ tooltip、所有键逐键目视：低风险，不要求穷举，可在预发布反馈中继续观察。

## 6. 最小门槛

- 发布预发布版前：至少完成 R-02、R-03、R-10、R-11、R-12、R-13；R-01/R-14/R-20 可以在预发布版首轮完成，但必须公开标注尚未验证范围。
- 标记稳定版前：R-01～R-14、R-20 全部 PASS，或对受环境限制项目作维护者明确豁免并写入已知限制。
