## 4. 26.2 与 26.3 的实现差异

共同逻辑：

1. 以 `(provider, binding ID)` 分组快照项和 live binding。
2. 唯一 `1:1` 组保持原有自动匹配。
3. 重复身份组只自动消费两侧均唯一的 exact-keys no-op。
4. 剩余 keys 不同的边作为歧义候选，默认不选择。
5. 手工选择同时强制 snapshot entry 与 live binding 双向一对一。
6. modifiers 仍只序列化，不参与差异判断或实际应用。

26.3 的附加保护：

- `ImportSelection.sanitize()` 首先取消全部 `!canApply()` 项。
- `ImportSelection.setSelected()` 拒绝重新选择 `!canApply()` 项。
- 复选框继续以 `match.canApply()` 控制 active 状态。
- Confirm 继续只执行 `selected && canApply()`。
- `ImportMatch.apply()` 自身仍会拒绝包含不支持规范键码的条目。

因此 F25 tombstone、未知扩展值与歧义默认未选择是叠加约束，不会相互覆盖。GUI 仍使用既有 26.3 显示名称逻辑展示不可用或不支持键码。
